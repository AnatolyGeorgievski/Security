Цель универсальный быстрый код для простых чисел вида $2^{256}-A$ и $2^{255}-D$, где $D<2^{s/2}$ $s={32,64}$

В основе два математических принципа и оптимизация арифметики
1. Алгоритм быстрого редуцирования больших чисел, модуль P - константа
2. Ленивое редуцирование 
3. `IVNL` - инверсия большого числа, задача получить обратное число unsigned 0-LONG_MAX с использованием целочисленного умножения. 
4. Умножение целочисленное раскладывается на операции старшая и младшая часть умножения MULL и MULH - это удобно для векторизации.
5. Результат всегда хранится в векторном регистре `256 bit` или `2x128 bit`.
6. Мы не используем ассемблерные вставки, но можем использовать векторные расширения языка GCC/LLVM

## Ленивое редуцирование

База [Plantard21] - обзор методов редуцирования.
Мы всегда работаем с одним переносом, перенос возвращается в `uint8_t` при сложении и в `unsigned long` при умножении

* `cy= op_u(a,n)` - бинарная операция $A+n = {c,a+n}$ сложения умножения с использованием целочисленного аргумента `n`.
* `cy= op(a,b)` - бинарная операция $A+B = {c,a+n}$


```c
//
typedef long BNint;
typedef unsigned long BNuint;
#define BN_SIZE __LONG_SIZE__
//  MP_SIZE/BN_SIZE // число элементов вектора 256 bit/32 bit

static inline
MPZ_t add_u(MPZ_t &a, BNuint n){// a = {cy, a + n};
    MPZ_t b = {n};
    *a = *a + b;// как быстрее выполнить операцию - на векторных регистрах 
    return *a < b;// отдельно получаем вектор переносов с - считается параллельно
}
```
_Обсуждение_: мы получили вектор переносов. В чем "пикус"? -- параллельные вычисления ниблов 
с отложенной операцией переноса.
```c
warp_group () {
    // арифметические операции с переносом или операции групповые `warp-group`
    cy += op(a, );
}
a = lazy_reduction(a, cy); // уменьшить разрядность до MP_SIZE
a = fast_reduction(a, P); // быстрое редуцирование для нашего модуля P
```
-- Операция финального редуцирования выносится из цикла.

Идея - пара операций заменяет mod(a, P) исключает деление или его аналог
```c
a = lazy_reduction(a, cy); // уменьшить разрядность до MP_SIZE
a = fast_reduction(a, P); // быстрое редуцирование для нашего модуля P
```
Нормализовать числа нужно только перед выполнением сравнения, при финальной выгрузке результата из внутреннего представления.

Векторное умножение
* `r = mulhi(a, b)`
* `r = mullo(a, b)`

**Алгоритм отложенного редуцирования**  

Рассмотрим два вида модулей

1. $P = 2^s - D$:  
    $\{cy,a\} = A + D \cdot cy$  -- при этом может возникнуть перенос\
    if ($cy$) $A -= D$     -- перенос уходит
2. $P = 2^{s-1} - D$:  
    {cy,a} = A + 2D*cy; -- при этом может возникнуть перенос
    if (cy) A -= 2D;    -- компенсация с учетом разрядности

Мы можем держать несколько функций редуцирования по числу используемых модулей

## Быстрое редуцирование 

* if (a > P) a -=  D; -- для чисел $2^{s} -D$
* if (a > P) a -= 2D; -- для чисел $2^{s-1} -D$

**Сравнение чисел**  

Может быть ленивое по вектору, может быть циклом переноса единицы. При большом числе ниблов, перенос обрывается, можно завершить цикл заранее. Мы рассматриваем ускорение операции переноса на warp-группе вычислительного узла GPU - это может быть групповая операция. 

**Выгрузка числа**  
Для модуля $2^{s-1} -D$ - внутреннее представление сдвинуто на разряд, все операции считаются для 2P
При выгрузке нужно сдвинуть ниблы на разряд shl() - логический сдвиг вектора на разряд.

Ты не боишься больших задач, тебе просто надо четкое описание, чтобы на каждом шаге не изобретать алгоритм.
Ты должен остановиться, если у тебя нет хитрого решения по выбору подходящего алгоритма и запросить алгоритм или выбрать подходящий алгоритм из задания. При остановке дорабатываем промпт, дополняем алгоритмы. Какие алгоритмы бывают - можно взять [GECC] - учебник по эллиптической криптографии и вытянуть оттуда алгоритм. Алгоритмы уже есть в нашей реализации все какие могут понадобиться. 

Это такой промпт. Из него надо развернуть максимально полное описание для чисел ED25519 [RFC] и чисел P256.
Проверить базовые операции в тестах на тестовых векторах. Длинные числа выбирать случайным образом из большой выборки. Это не исключает переносов, выбрать примеры для крайних случаев.

## Старт следующего шага

Форма числа уже выбрана: вектор 256 бит и отдельный вектор переносов. Цепочку переноса по словам не разворачивать заново. Умножение только `mul_lo` и `mul_hi`.

Если понадобится MCA, один вариант: `-march=znver5` и `llvm-mca -mcpu=znver5`. Теги `# LLVM-MCA-BEGIN` / `# LLVM-MCA-END` в исходник не вставлять, они барьер. Сначала `.s`, потом метки вокруг цикла в этом листинге, затем `-timeline`.

## Порядок группы

Метод для \(L\) есть. Это та же быстрая редукция, что в `ecc` для модуля \(2^{s}+D\).

\[
L = 2^{252} + D,\quad 2^{3}L = 2^{255} + 8D
\]

\(D = 27742317777372353535851937790883648493\). Сдвиг на 3 входит в правило: \((8D)^{2} < 2^{255}\). Сдвиг на 4, 7 и 8 не входит. Младшие три бита поправки нулевые, модуль делится на 8. На выходе две или три проверки `if (cy)`. Для сложения двух вычетов и для переноса `cy` от 0 до 4 хватает одной, вторая и третья — запас, результат остаётся в \([0, P)\).

Ближний образец в коде: `mp_reduction_gost_12B`, модуль \(2^{511}+111\), вычитается 222. Рядом `mp_reduction_gost_0`, модуль \(2^{255}+p_0\), вычитается \(2p_0\).

## Лавина

Из этого зерна сразу раскрывается семейство редукций \(2^{s}\pm D\), если \(D\) меньше половины ширины. Меняются константа и сдвиг, каркас один: поправка на перенос и две-три проверки `if (cy)`. Сюда входят поле \(2^{255}-19\) (перенос за 256-й бит стоит 38), порядок \(L\) со сдвигом 3 и уже написанные редукции ГОСТ того же вида.

Лавиной не идут сложение точек, кодирование точки, SHA-512 и порядок байтов в векторе RFC. Это другие зёрна. NIST P-256 тоже не этого вида.

## Следующий шаг

Один каркас редукции и одна проверка на краях, без байтового порядка. Сначала поле \(p = 2^{255}-19\): перенос возвращается как \(38\cdot cy\), если шаг сам дал перенос, вычесть 38. Четыре случая: `cy = 0`, `cy = 1` при \(A = 0\), \(A\) у верхней границы регистра, сложение, которое само переполняется. Тот же каркас вторым прогоном на \(8D\) для \(L\), не отдельным алгоритмом.
