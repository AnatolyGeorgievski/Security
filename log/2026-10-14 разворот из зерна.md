# Разворот из зерна

> ::TAGS:: класс, мост, зерно, квант, остаток, обратимость, this, префикс, что-как, canon, покрытие, rdtsc, throughput, mca, изгиб, шаблон, ggml, дерево, шаг, ntt, rns, prng, qnn, тензор, barrett, montgomery, plantard, lazy, rpc

🧩 Из концепта в `2026-10-14 Заново изобретаем простые числа.md` развёрнуты только те алгоритмы, которые в нём уже названы. Код и тесты этим шагом не пишутся.

Зерно задаёт два модуля и одну пару операций вместо деления.

- $P = 2^{s} - D$, $D$ малое.
- $P = 2^{s-1} - D$.

Слово `BNuint` — `unsigned long`. Вектор результата — 256 бит, то есть четыре слова по 64 бита на этой машине, либо восемь слов по 32. Перенос сложения — `uint8_t` на дорожку. Перенос умножения — `unsigned long`. Старшая и младшая половины произведения — `mulhi` и `mullo`. Ассемблерных вставок нет, вектор — расширение GCC.

Нормальная форма нужна перед сравнением и перед выгрузкой. Внутри цикла остаётся пара

```
a = lazy_reduction(a, cy);
a = fast_reduction(a, P);
```

Финальный вызов вынесен из цикла.

## Ленивое редуцирование

Форма $2^{s}-D$:

```
{cy, a} = A + D * cy
if (cy) A = A - D
```

Форма $2^{s-1}-D$:

```
{cy, a} = A + (2*D) * cy
if (cy) A = A - (2*D)
```

Быстрое редуцирование после этого, как в зерне:

- для $2^{s}-D$: если $a > P$, то $a = a - D$;
- для $2^{s-1}-D$: если $a > P$, то $a = a - 2D$.

Сравнение — по вектору, с ранним выходом, когда перенос оборвался.

## Ed25519, поле

Модуль поля из RFC 8032:

```math
p = 2^{255} - 19
```

Это вторая форма: $s = 256$, $D = 19$, $2D = 38$.

Два веса переноса, оба следуют из $2^{255} \equiv 19 \pmod p$:

- бит 255 внутри вектора стоит $D = 19$;
- перенос за бит 256 стоит $2^{256} \equiv 38 \pmod p$.

Поэтому сложение двух чисел в 256-битном векторе с переносом `cy` за границу регистра:

```
{cy2, a} = A + 38 * cy
if (cy2) A = A - 38
```

Выгрузка для этой формы, как в зерне: внутреннее представление сдвинуто на разряд, операции идут для $2p = 2^{256}-38$, наружу вектор сдвигается на один разряд влево (`shl`).

Тот же приём без сдвига представления — сложить бит 255 с весом 19. Это первая форма на границе $2^{255}$. Оба приёма сидят в зерне. В код берётся один, когда дойдём до теста.

Групповой порядок Ed25519

```math
L = 2^{252} + 27742317777372353535851937790883648493
```

этой парой формул не редуцируется. 🧩 Здесь остановка: для $L$ нужен отдельный алгоритм.

## Что в зерне ещё есть, и это не поле Ed25519

`INVL` — обратное к одному слову через целочисленное умножение, в новом `mp.c` это `~(uint128_t)0 / v`. Оно нужно, когда модуль не вида $2^{s}-D$. Для $D = 19$ ленивая формула обходится без `INVL`.

Первая форма уже есть в старом дереве: ТК 26, paramSetA, $p = 2^{256}-617$, редукция `mp_reduction_gost_A`. $A = 617$ играет роль $D$.

## P-256

Модуль NIST P-256

```math
p = 2^{256} - 2^{224} + 2^{192} + 2^{96} - 1
```

не есть $2^{256}-A$ с малым $A$ и не есть $2^{255}-D$. Формулы зерна к нему не применяются.

В `ecc.c` для него уже лежит отдельный алгоритм, `mp_reduction_nist_p256`: поправка из восьми 32-битных слов и один вычитающий проход. В таблице кривых у NIST P-256 стоит признак FIPS. 🧩 Этот модуль берётся первым. Новая функция редукции для него не пишется.

## Два шага

🧩 Шаг 1, этот. Проверенный модуль — `mp_reduction_nist_p256`. Шаблон гоняет эту одну функцию после сложения и после умножения. Края: $0$, $P-1$, ${\sim}0$. Выборка: 1024 числа из `getrandom`. В теле функции остаётся пометка, что перенос `cx = 0xFFFFFFFF` и `cx = 1` ещё под вопросом. Эти два края входят в тот же прогон.

Шаг 2, не этот. Поле Ed25519, одна функция редукции, тот же шаблон. Второй приём со сдвигом представления и порядок $L$ в шаг 2 не входят.

## Класс BN

🧩 Таблица сложена из вызовов `ecc.c` и тел `mp.h`, `bn_asm.c`. Имена с суффиксом ширины — параметр класса, не отдельные операции. Модульные `mp_addm`, `mp_subm`, `mp_mulm`, `mp_invm` и `mp_reduction_*` в класс не входят: они зовут эти шаблоны и сами знают модуль.

| Шаблон | Метод | Операнды | Перенос | Имена в ecc |
| --- | --- | --- | --- | --- |
| `cy = op(a, b)` | add, sub | 2 вектора | бит | `bn_add`, `bn_sub`, `bn_add1`, `bn_sub1` |
| `cy = op_n(a, n)` | add_n, sub_n | вектор и слово | бит | `bn_add_ui`, `bn_sub_ui`, `bn_add_1_256`, `bn_add_1_512` |
| `cy = op_n(a, n)` | mul_lo | вектор и слово | слово, это `mul_hi` | `bn_mul_ui` |
| `cy = op(r, a, n)` | mac | 3: аккумулятор, вектор, слово | слово | `bn_mac_ui`, `bn_mla_1_256`, `bn_mla_256`, `bn_mla_1_512`, `bn_mla_256_512`, `bn_mla_128_256` |
| `cy = op(r, a, n)` | mls | 3: аккумулятор, вектор, слово | слово | `bn_mls_ui`, `bn_mls_1_256`, `bn_mls_256`, `bn_mls_1_512`, `bn_mls_512`, `bn_mls_128_256` |
| `cy = op(a)` | shl, shr | 1 вектор | бит | `bn_shl`, `bn_shr`, `bn_shr1`, `bn_shrl` |
| без переноса | set0, set1, neg, mov | 1 вектор | нет | `bn_set_0`, `bn_set_1`, `bn_set_neg`, `bn_move` |
| предикат | eq, le, is_zero, is_one | 1 или 2 вектора | нет | `bn_equ`, `bn_le`, `bn_is_zero`, `bn_is_one` |
| бит | bit | вектор и номер бита | нет | `bn_bit_test`, `bn_bit_val` |

Перенос сложения — бит на дорожку, отдельным вектором. Перенос умножения — старшее слово: у `mul_lo` это `mul_hi`, у `mac` и `mls` то же слово. Пары `{hi, lo}` в классе нет. `bn_add1` и `bn_sub1` — тот же `add` и `sub`, приёмник совпадает с первым операндом.

## Эталон целого

🧩 С классом BN стыкуется один прибор: `mpz_add`, `mpz_sub` и `mpz_mul` из R3-lib. Два 32-битных слова BN укладываются в один 64-битный лимб `mpz`. Сверяется целое значение вектора. Пословный бит переноса BN этот прибор не показывает: перенос `mpz` выходит раз в 64 бита.

`mpz_mod` в это зерно не входит. Он берёт `INVL` старшего лимба и ждёт длину модуля, кратную 64. Ленивая формула $2^{s}-D$ обходится без `INVL`. Поле Ed25519 и порядок $L$ этой сверкой не закрываются. P-256 взят отдельным модулем, не этой формулой.

Код и тест этим шагом не пишутся.

## Форма разворота

Базовый принцип QNN — математические классы. Это зерно математики в программировании. Математика вводится с прямым мостом на класс: объект математики и класс — одна сущность. Это центральная связка. В Си класс языком не объявляется. Метод, параметр и покрытие принадлежат ему.

Пишем на Си. Класс держится в голове: один модуль $P$, одна ширина слова $W$, набор методов. В файле метод — функция. Ширина и простое — параметры класса, не отдельные алгоритмы.

Объектное мышление при чистом Си — правило качества. Класс задаёт, какой метод добавляется и какое покрытие ему принадлежит. Си не прячет это в язык: нет наследования и нет неявного `this`. Граница метода видна в списке аргументов и в дереве вызовов. `this` — всегда первый аргумент. Имя функции начинается с имени класса: `bn_`, `mpz_`, `mp_`. Дальше порядок слов `префикс_что_как`: `g_string_size_get` чаще, чем `get_size`. Шаг, который добавляет метод без покрытия `canon`, класс не расширяет.

Изгиб местности — второе правило. Новый инструмент сначала ищется в уже лежащем рельефе: заготовка, статическая таблица, макрос, переменная среды. Код без кода — это смена такой точки, после которой имеющаяся заготовка работает как другой инструмент. Сюда входят определение макроса, пополнение статической таблицы и подстановка уже написанной функции. Новый метод пишется, когда изгиба не хватило.


Сравнение методов идёт по каноническому выводу, не по тому, как устроены переносы внутри.

```math
\operatorname{canon}(a) = a \bmod P, \qquad 0 \le \operatorname{canon}(a) < P
```

Два метода сошлись, когда их `canon` равны. Промежуточные слова, порядок вычитаний и ширина лимба в это равенство не входят.

### Шаблон

```
template<P, W>
class Field {
    const prime : Vector<W, 256>;          // BN2, младшее слово первое
    canon(a)           = a mod P;
    reduce(a, cy) -> b,   canon(b) = canon(a + cy · 2^256);
    addm(a, b)    -> c,   canon(c) = canon(a + b);
    mulm(a, b)    -> d,   canon(d) = canon(a · b);
}
```

`add` и `mul` живут в классе BN. Они модуля не знают. `reduce`, `addm` и `mulm` живут в `Field`: они знают $P$ и отдают `canon`.

Покрытие одного шага — одно и то же множество:

```math
\operatorname{Cov} = \{0,\; P-1,\; {\sim}0\} \cup \operatorname{Sample}(1024)
```

`Sample` берётся из `getrandom`. На каждом элементе покрытия считаются оба метода и сверяется `canon`.

Горячий цикл смотрится отдельно от `canon`. В тестах замер — методы `test_clk_begin` и `test_clk_end` в `test/clk.h`: первое чтение `__builtin_ia32_rdtsc` перед циклом, второе после, наружу уходит разность. Тело цикла остаётся в тесте. Так же пара стоит в `src/crc16_clmul.c`. Полная методика пропускной способности, со сравнением хэш-функций и генераторов: `lfence` перед чтением, `__rdtscp` в начале и в конце, несколько проходов, в зачёт берётся минимум, наружу — такты на семпл. Она записана в [Throughput.md](https://github.com/AnatolyGeorgievski/MWC128/blob/main/Throughput.md). Разбор внутри цикла уже записан в `log/2026-10-14 принципы оптимизации.md`: метки `# LLVM-MCA-BEGIN` и `# LLVM-MCA-END` в исходник не ставятся, `__asm__ volatile` режет разворот цикла. Сначала `.s`, потом метки вокруг получившегося цикла, затем `llvm-mca -timeline`.


### Дерево методов

Кто кого вызывает. Это состав класса, не устройство формулы.

```
Field<P, W>
├── prime                 BN2
├── reduce(a, cy)
│     ├── add1
│     └── sub1
├── addm(a, b)
│     ├── add             класс BN
│     └── reduce
└── mulm(a, b)
      ├── mul             класс BN
      └── reduce
```

Ширина $W$ — параметр того же метода, не новый класс. `reduce` при $W = 32$ и `reduce` при $W = 64$ сравниваются так:

```math
\operatorname{canon}(\operatorname{reduce}_{32}(a, cy)) = \operatorname{canon}(\operatorname{reduce}_{64}(a, cy)) = \operatorname{canon}(a + cy \cdot 2^{256})
```

В файле `src/ecc_256.c` шестидесятичетырёхбитный метод зовёт тридцатидвухбитный как носитель формулы. Для канона это один метод.

### Что добавляется в класс

Шаг добавляет один метод и покрытие этого метода. Следующий метод не добавляется, пока `canon` текущего не сошёлся.

1. В класс добавляется `prime` через `BN2`. Покрытие: целое значение константы одно при $W = 32$ и при $W = 64$.
2. В класс добавляется `reduce`. Покрытие: равенство `canon` на `Cov` для обеих ширин и для $a + cy \cdot 2^{256}$.
3. В класс добавляется `addm`. Покрытие: $\operatorname{canon}(\operatorname{addm}(a, b)) = \operatorname{canon}(a + b)$ на `Cov`.
4. В класс добавляется `mulm`. Покрытие: $\operatorname{canon}(\operatorname{mulm}(a, b)) = \operatorname{canon}(a \cdot b)$ на `Cov`.

🧩 Сейчас в `Field` для NIST P-256 лежат `prime` и `reduce`. Следующее добавление — покрытие `canon` для `reduce`. `addm` и `mulm` этим шагом не добавляются.

Экземпляр шаблона после P-256 — поле Ed25519: то же дерево, другое $P$, другой `reduce`. Он начинается, когда покрытие `reduce` у P-256 сошлось.

## Каталог редуцирования в QNN

Разбор: [ZeroKnowledge.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/ZeroKnowledge.md), приложение A. Метод выбирается по тому, какую часть числа он трогает.

- Барретт, A.1, A.1.1, C.6. Старшая часть, заранее $\lfloor 2^L/q \rfloor$. Поправка $r \ge q$ может остаться за циклом — это и есть lazy.
- Монтгомери, A.2, A.8, A.8.1. Младшая часть, $q' = -q^{-1} \bmod R$, ответ $z R^{-1}$. Знаковый вариант сходится к трём умножениям.
- Шуп и бабочка Харви, A.4–A.6. Умножение на константу, $\lfloor W\beta/q \rfloor$. Диапазон $< 4q$ снимает часть поправок.
- NTT-friendly, A.9–A.9.2 и C.7. Модуль $p = K\cdot 2^s \pm 1$, свёртка $x_1 - K x_0$. Это сторона хэша и PRNG, место разработки — MWC128.
- Ленивое многословное, A.10. $p = 2^n - K$, вход $\{x, c\}$, перенос $c$ гасится вычитанием $c\cdot p$. Модули NIST этому удовлетворяют. `mp_reduction_nist_p256_32` — этот метод. Покрытие `canon` сравнивает его вывод, новый редуктор этим шагом не добавляется.
- Плантар, A.11–A.12. Слово, $R = p^{-1} \bmod \beta^2$, умножение на константу в NTT. Для 256-битного поля не берётся.
- RNS в MRS, A.13. Сторона RNS-HASH.
- $q = 2^{64}-2^{32}+1 = \varphi^2-\varphi+1$, $\varphi = 2^{32}$, $\varphi^3 \equiv -1$. После умножения $x_0 + \varphi^2 x_1 + \varphi^3 x_2$ сворачивается в $x_0+(\varphi-1)x_1-x_2$.

🧩 RPC в [Тестирование и настройка.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/%D0%A2%D0%B5%D1%81%D1%82%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%B8%20%D0%BD%D0%B0%D1%81%D1%82%D1%80%D0%BE%D0%B9%D0%BA%D0%B0.md) — следующий фрагмент, к `netd`. Команды `GET_TENSOR`, `SET_TENSOR`, `COMPUTE_GRAPH`, хеш тензора вместо повторной пересылки, CoAP. В этот шаг не входит.

## Зерно, которое помним

Математические классы — зерно. Источник: [MATHAN.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/MATHAN.md). Структура задаётся множеством и методами. Группа, кольцо, поле, тело — классы. Разворот в Си тот же: один класс, один метод, покрытие `canon`.

Квантизация и округление в текущий шаг `Field` не входят. Их надо помнить.

Компенсация ошибки округления — центральный тезис R3 RTOS. Время задаётся рациональной дробью. Квант времени $\tau$ несёт целую долю и остаток. Остаток, не вошедший в этот такт, добавляется в следующий. Замена деления умножением и сдвигом (A.7) считает ту же дробь. В манифесте R3 это строка «таймеры с фазовой компенсацией», статус «не явно».

В QNN на этом держатся детерминированность и обратимость по шагам. [README.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/README.md): квантизатор меняет разрядность и квантует величину с компенсацией остатка и с дискретизацией по времени. [QUANT.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/QUANT.md): непрерывность дискретного времени — суммирование и компенсация остатка; класс величины — целое и остаток на $[0,1)$; квантизатор $y = \lfloor x + Z(x-y) \rfloor$. Обратный оператор существует, когда квантовое состояние полно. [FPQUANT.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/FPQUANT.md): дробь $A/B$ и фиксированная точка ошибки квантования не создают, плавающая точка её создаёт и должна компенсировать. [LOGIC.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/LOGIC.md): остатки округления и регистры $Z$ — полное состояние; программа, сохранившая его, читается в обе стороны. Стохастическое округление в [LLaMa.md](https://github.com/AnatolyGeorgievski/QuantumNN/blob/main/LLaMa.md) и в ZeroKnowledge завязано на тот же остаток: ошибка не отбрасывается, а возвращается в данные.

## Образец: ggml-opencl

Подборка ядер: `QuantumNN/inbox/ggml-opencl/kernels/`. Язык — OpenCL C. Это образец разворота класса из зерна.

Зерно унарной операции — макрос `KERNEL_UNARY(op, type)` в `ggml-opencl.cl` и `ggml-opencl_la.cl`. Тело одно: прочитать `src0[gid]`, записать `dst[gid] = op(x)`. Строка `KERNEL_UNARY(silu, float)` добавляет в класс `float` метод `kernel_silu`. Строка `KERNEL_UNARY(silu_f16, half)` добавляет тот же метод в класс `half`. Новый алгоритм не пишется.

Одно имя на несколько типов даёт `__attribute__((overloadable))`. `_sub_group_block_read` и `vec_dot` выбираются по типу аргумента: `half`, `float`, `block_q8_0`, `block_q8_1`. Тип аргумента здесь и есть класс. Суффикс ширины (`_k16`, `_k32`) остаётся, когда перегрузка по типу аккумулятора не различает шаг.

Эмуляция и аппаратный путь — две реализации одного метода. `_matrix_mad_f16_f16_k16` при `cl_intel_subgroup_matrix_multiply_accumulate` зовёт `intel_sub_group_f16_f16_matrix_mad_k16`, иначе считает `sub_group_broadcast` и умножение. Снаружи имя одно.
